# net-check — Руководство пользователя

## Что это такое

**net-check** — инструмент диагностики сетевого подключения и контроля деградации для роутеров Keenetic с Entware. Проверяет доступность ресурсов через все WAN-интерфейсы, обнаруживает MITM/DPI-аномалии, анализирует CDN geo-steering, тестирует DNS-утечки и сравнивает качество маршрутов.

### Зачем это нужно

- **Проверка split-routing** — убедиться, что трафик идёт через нужный интерфейс (ISP/туннель)
- **Обнаружение сетевых аномалий** — определение ISP-фильтрации, DPI-вмешательства, подмены DNS
- **Диагностика CDN** — проверка geo-steering (получаете ли вы ближайший CDN-узел)
- **DNS-утечки** — проверка, что DNS-запросы не утекают мимо шифрованного канала
- **TLS-безопасность** — обнаружение MITM-прокси и подмены сертификатов
- **Сравнение путей** — задержка, jitter, потери пакетов на каждом WAN-интерфейсе

## Требования

- Роутер Keenetic с Entware
- **KeeneticOS 5.0+**

### Программные зависимости

**Из Entware-репозитория** (устанавливаются автоматически):

| Пакет | Назначение |
|-------|-----------|
| `curl` | HTTP-проверки, GeoIP-сервисы, DNS-leak API |
| `bind-dig` | DNS/CDN-проверки, EDNS Client Subnet, DNS-leak probing |
| `iputils-ping` | ICMP-проверки, измерение потерь и jitter |

**Из Entware-репозитория** (рекомендуемые):

| Пакет | Назначение |
|-------|-----------|
| `netcat` | TCP connect проверки |
| `openssl-util` | Инспекция TLS-сертификатов |
| `traceroute` | Трассировка маршрута |

**Из проекта keenetic-entware-extras** (устанавливаются вручную):

| Пакет | Назначение |
|-------|-----------|
| `keenetic-entware-extras` | Общие библиотеки проекта (обязательно) |

## Установка

### Шаг 1. Установить зависимости проекта

```sh
opkg install keenetic-entware-extras_<версия>_all.ipk
```

### Шаг 2. Установить пакет

```sh
opkg install net-check_<версия>_all.ipk
```

Зависимости `curl`, `bind-dig`, `iputils-ping` установятся автоматически.

### Шаг 3. Проверить работу

```sh
net-check.sh all
```

## Использование

### Основной скрипт

```sh
net-check.sh <команда> [аргументы]
```

### Команды

| Команда | Описание |
|---------|----------|
| `all` | Полная диагностика (9 шагов: geo → conn → ipv6 → dns → dns-leak → comp → cdn → tls → speed) |
| `check <домен>` | Глубокая проверка одного ресурса (HTTP + DNS + TLS + CDN) |
| `geo` | Проверка точки выхода (GeoIP) на каждом WAN-интерфейсе |
| `conn` | TCP/TLS timing, traceroute, потери пакетов, MTU |
| `ipv6` | Обнаружение IPv6-утечек |
| `dns` | DNS-резолвинг и обнаружение ISP-фильтрации |
| `dns-leak` | Тест DNS-утечек (обнаружение цепочки резолверов) |
| `comp` | Таблица сравнения HTTP-доступности |
| `cdn` | Анализ CDN geo-steering |
| `tls` | Проверка TLS-сертификатов на MITM |
| `speed` | Тест пропускной способности (download/upload) |

### Примеры

**Полная диагностика:**
```sh
net-check.sh all
```

**Глубокая проверка одного домена:**
```sh
net-check.sh check youtube.com
```

**Глубокая проверка нескольких доменов (bulk-таблицы):**
```sh
net-check.sh check youtube.com google.com github.com
```

**Проверки по отдельности:**
```sh
net-check.sh geo              # GeoIP на каждом интерфейсе
net-check.sh conn             # Connectivity: timing, traceroute, потери
net-check.sh dns              # DNS-резолвинг всех целей
net-check.sh cdn youtube.com  # CDN-анализ одного домена
net-check.sh tls youtube.com  # TLS-проверка одного хоста
```

**Bulk-проверки с пользовательскими доменами (вместо конфига):**
```sh
net-check.sh comp youtube.com google.com
net-check.sh dns youtube.com google.com
```

### Флаги

| Флаг | Описание |
|------|----------|
| `--json` | Вывод в формате JSON |
| `--privacy` | Анонимизация IP-адресов, ASN, geo в выводе |
| `--iface <имя>` | Проверка через конкретный интерфейс |
| `--quiet` | Однострочная сводка по каждой секции |
| `--verbose` | Расширенный вывод (timing waterfall) |
| `--no-color` | Отключить цветной вывод |
| `--help` | Справка по использованию |

**Примеры с флагами:**
```sh
net-check.sh --json check youtube.com   # JSON-вывод
net-check.sh --privacy all              # Скрыть IP/ASN/geo
net-check.sh --iface nwg0 comp         # Только через nwg0
net-check.sh --quiet all                # Краткая сводка
net-check.sh --verbose conn             # Подробный timing
```

## Конфигурация

Файл конфигурации: `/opt/keenetic-entware-extras/net-check/config/config.conf`

> 📝 `conffile` — ваши изменения сохраняются при `opkg upgrade`.

> 📝 Значения по умолчанию в `config/defaults.conf`. В `config.conf` указывайте только отличия.

### Параметры

#### Интерфейсы и сеть

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `CHECK_INTERFACES` | `""` (авто) | WAN-интерфейсы для проверки. Пусто = автоопределение всех WAN |
| `LAN_BRIDGE` | `"br0"` | LAN-бридж |

#### Connectivity

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `CONNECTIVITY_TARGET` | `"8.8.8.8"` | IP для traceroute, ping (потери/jitter), MTU probes |
| `CONNECTIVITY_URL` | `"https://www.gstatic.com/generate_204"` | HTTP endpoint для проверки связи |

#### Таймауты (секунды)

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `HTTP_TIMEOUT` | `10` | Таймаут HTTP-запросов |
| `CONNECT_TIMEOUT` | `5` | Таймаут TCP-подключения |
| `DNS_TIMEOUT` | `2` | Таймаут DNS-запросов |
| `PROBE_TIMEOUT` | `2` | Таймаут ICMP/traceroute зондов |
| `SPEED_TIMEOUT` | `30` | Таймаут speed-тестов |
| `GEOIP_TIMEOUT` | `3` | Таймаут GeoIP-сервисов |

#### Зона

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `CHECK_ZONE` | `"auto"` | Зона для фильтрации целей. `"auto"` = из smartdns-geo-conf, явная = ISO 3166-1 или союз, `""` = без зоны |

#### HTTP / curl

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `MAX_REDIRS` | `10` | Максимум HTTP-редиректов |
| `CURL_UA` | `"Mozilla/5.0 (compatible; net-check/1.0)"` | User-Agent для curl-запросов |

#### DNS

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `DNS_LEAK_CHECK_DOMAIN` | `"whoami.akamai.net"` | Домен для DNS leak check |
| `DNS_CACHE_TTL` | `60` | TTL DNS-кэша (секунды) |
| `SMARTDNS_PORT` | `6053` | Порт SmartDNS |
| `DNS_PROBE_PORTS` | `"53 6053 5353"` | Порты для обнаружения DNS-серверов |

#### GeoIP-сервисы

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `GEO_SERVICES` | *(ifconfig.me, ipify, ipinfo)* | Сервисы определения публичного IP (в порядке приоритета) |
| `GEOIP_SERVICES` | *(ip-api, ipinfo)* | Сервисы IP→geo (в порядке приоритета) |
| `GEO_CACHE_TTL` | `1800` | TTL geo-кэша интерфейсов (30 мин) |
| `IPGEO_CACHE_TTL` | `86400` | TTL общего IP→geo кэша (24 часа) |

#### Speed test

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `SPEED_TEST_BYTES` | `1000000` | Размер данных для теста скорости (1 МБ) |

#### Traceroute / Ping

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `TRACEROUTE_MAX_HOPS` | `15` | Максимум хопов traceroute |

#### CDN Steering

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `CDN_ECS_RESOLVER` | `"8.8.8.8"` | Резолвер для EDNS Client Subnet (ECS) запросов |

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `PARALLEL_BATCH_SIZE` | `auto` | Размер batch для параллельных проверок. `auto` = адаптивно |
| `CDN_BATCH_SIZE` | `auto` | Размер batch для CDN-проверок. `auto` = адаптивно |

#### Process priority

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `NICE_ADJUST` | `10` | Приоритет процесса (0=отключено, 1-19=ниже приоритет) |

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `DEGRADED_TTFB_RATIO` | `3` | Порог отношения TTFB для определения деградации |

#### Verbosity & Output

| Параметр | По умолч. | Описание |
|----------|-----------|----------|

| Параметр | По умолч. | Описание |
|----------|-----------|----------|
| `DATA_DIR` | `"/opt/tmp/net-check"` | Каталог кэша и результатов |

#### DNS Leak Test

| Параметр | По умолч. | Описание |
|----------|-----------|----------|

## Конфигурационные файлы

Все файлы конфигурации защищены от перезаписи при обновлении пакета.

| Файл | Описание |
|------|----------|
| `config/defaults.conf` | Значения по умолчанию (**не редактировать**) |
| `config/config.conf` | Пользовательские переопределения (создать при необходимости) |
| `config/check-targets.conf` | Список целей для HTTP/DNS/TLS проверок |
| `config/check-targets-custom.conf` | Пользовательские цели (не перезаписывается) |
| `config/cdn-domains.conf` | Домены для CDN geo-steering анализа |
| `config/cdn-domains-custom.conf` | Пользовательские CDN-домены (не перезаписывается) |
| `config/dns-providers.conf` | Паттерны идентификации DNS-провайдеров |
| `config/anomaly-markers.conf` | Маркеры ISP-блокировок (обнаружение подмены страниц) |
| `config/mitm-issuers.conf` | Паттерны CA известных MITM-прокси |
| `config/known-cas.conf` | Известные национальные/региональные CA (allowlist) |
| `config/privacy-providers.conf` | Паттерны privacy-провайдеров для анонимизации |
| `config/wellknown-ips.conf` | Известные IP публичных DNS-резолверов |

### Пользовательские цели

Для добавления своих целей проверки используйте файлы с суффиксом `-custom.conf`:

- **`check-targets-custom.conf`** — добавить домены для HTTP/DNS/TLS
- **`cdn-domains-custom.conf`** — добавить домены для CDN-анализа

Эти файлы **не перезаписываются** при обновлении пакета.

## domain-check.sh

Ярлык для быстрой глубокой проверки одного ресурса. Эквивалент `net-check.sh check <домен>`:

```sh
domain-check.sh youtube.com
domain-check.sh https://example.com/path
```

Принимает домены и URL. Выполняет HTTP + DNS + TLS + CDN анализ в одном вызове.

## Диагностика и exit codes

| Код | Значение |
|-----|----------|
| `0` | Все проверки пройдены |
| `1` | Деградация (некоторые проверки не пройдены) |
| `2` | Критическая ошибка |

Вердикты в выводе:

| Символ | Значение |
|--------|----------|
| ✓ | Проверка пройдена |
| ✗ | Проверка не пройдена |
| ⚠ | Предупреждение (частичная проблема) |

## Troubleshooting

### net-check.sh не найден

Убедитесь, что путь `/opt/keenetic-entware-extras/net-check/scripts/` в `$PATH`, или вызывайте по полному пути:

```sh
/opt/keenetic-entware-extras/net-check/scripts/net-check.sh all
```

### GeoIP-сервисы недоступны

Проверьте интернет-подключение. GeoIP-сервисы (ifconfig.me, ipify, ipinfo) используются для определения публичного IP. При недоступности всех сервисов geo-проверка будет пропущена.

### DNS-проверки не работают

- Убедитесь, что `bind-dig` установлен: `opkg list-installed | grep bind-dig`
- Проверьте доступность DNS-серверов: `dig google.com @8.8.8.8`

### TLS-проверка показывает ошибки

- Установите `openssl-util`: `opkg install openssl-util`
- Если TLS-проверка показывает MITM — проверьте, нет ли прозрачного прокси в сети

### Speed test медленный или таймаутится

- Увеличьте `SPEED_TIMEOUT` в `config.conf`
- Уменьшите `SPEED_TEST_BYTES` для более быстрого теста

### Высокая нагрузка на CPU

- Увеличьте `NICE_ADJUST` (по умолч. 10) для снижения приоритета
- Уменьшите `PARALLEL_BATCH_SIZE` до фиксированного значения (напр. `2`)

### DNS leak test не обнаруживает утечки

- Увеличьте `DNS_LEAK_WAIT` (по умолч. 7с) — для multi-tunnel нужно больше времени
- Увеличьте `DNS_LEAK_PROBE_COUNT` (по умолч. 5) для более надёжного обнаружения

## Стандарты

Методология измерений соответствует ITU-T Y.1540 (параметры передачи IP-пакетов) и ITU-T Y.1541 (целевые показатели производительности сети).
